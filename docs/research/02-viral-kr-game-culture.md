# 02. 한국에서 캐주얼/소셜 웹게임이 퍼지고 남는 이유 (2024~2026)

- 조사일: 2026-11-26
- 대상 게임: "도를 아십니까? — 교주 시뮬레이터" (3D 로우폴리 실시간 멀티 풍자 웹게임)
- 조사 방법: 웹 검색 + 원문 열람. 직접 연 페이지는 문서 끝 "출처 A", 검색 요약으로만 본 것은 "출처 B"로 구분했다.
- 표기 규칙: **[확인]** = 원문에서 읽음 / **[요약]** = 검색 결과 요약으로만 확인 / **[추론]** = 근거에서 내가 끌어낸 판단 / **확인 못함** = 근거를 못 찾음

## 0. 한 페이지 요약

1. **지금(2026년 11월) 한국은 "링크 하나로 들어가는 3D 웹 공간" 붐의 한복판이다.** 온라인 절 '산사'가 10/26 공개 후 사흘 60만, 일주일 100만 방문을 찍었고, 가상공간 집계 사이트 '메타모아' 등록 수가 10/30 71개 → 11/10 843개(10일간 약 +1,087%)로 늘었다. 우리 게임은 이 흐름의 "밈으로 비튼 변종 + 실제 게임 루프"에 해당한다.
2. **퍼지는 조건은 4가지로 수렴한다.** (a) 설치·가입·로그인 0, 3초 입장 (b) 친구에게 한 문장으로 설명되는 행동 (c) 결과물이 "나만의 것"으로 보이는 1장짜리 이미지 (d) 같이 들어와야 더 웃긴 구조.
3. **밈으로 비튼 사이트는 "빨리 퍼지고 빨리 사라진다"**(산사 파생 300여 개를 분류한 뉴스레터의 평가). 협동 파티게임(friendslop)도 D30 리텐션이 평균 3% 안팎이다. 그래서 장기 메타보다 **공유 루프와 서버 탄력성**에 먼저 투자한다.
4. **가장 큰 리스크는 제목 자체다.** "도를 아십니까"는 실제 길거리 포교 관행(2인 1조 접근, 금전 요구, 합숙 피해 보도)을 가리키는 말이다. 실제 수법의 디테일은 하나도 재현하지 않고, 첫 문장부터 엉뚱한 소재(라면, 퇴근)로 꺾는 방식만 허용해야 한다.
5. **현재 설계의 3룸 x 20명 = 동접 60명은 바이럴 시 첫날에 터진다.** 산사는 방석 20개로 시작해 다음 날 서버가 죽었고, 사흘 만에 1만 석으로 늘렸다. 대기열 화면까지 "콘텐츠"로 만들어 둬야 한다.

### 1.2 파생 붐과 분류

- 산사 공개 3일 만에 파생 서비스 약 300여 개(아시아경제 11/2 기준 인용), 메타모아 등록 843개(11/10). [확인] 트렌디움, 헤럴드경제
- 파생 방식 3갈래(트렌디움 분류) [확인]
  - A. 장르만 교체(사우나, 온천, 독서실): 안전하지만 차별점이 소재뿐
  - B. 대화를 다시 넣기(혼술바, 한강공원): **신고·욕설·모더레이션 부담**이 따라옴
  - C. 밈으로 비틀기(주식·코인 기원 '가즈아법당'): **빨리 퍼지고 빨리 사라짐**
- 우리 게임은 C에 가깝지만 실제 게임 루프(확률 포교, 랭크, 대결)가 있다. C의 약점인 "한 번 웃고 끝"을 2~3장의 훅으로 메워야 한다. [추론]
- 빅데이터 업체 썸트렌드는 이 현상을 "조용한 공존감(quiet co-presence)"으로 설명했다. [확인] 헤럴드경제
- 고구마팜(11/11)의 기획 팁: **"친구에게 뭐라고 설명하며 보낼까?"를 먼저 적어라.** 한 문장만 들어도 무엇을 하는지 궁금해지고, 링크를 열면 그 행동을 바로 해볼 수 있어야 한다. [확인]

### 4.1 항목별 상세

**1. 3초 무가입 입장 + 자동 닉네임 + 인앱 브라우저 대응 (M / 5)**
- 무엇: 링크를 열면 가입·닉네임 입력 없이 바로 거리 위에 선다. 닉네임은 "수상한 행인 4821"처럼 자동 생성하고 나중에 바꿀 수 있다. HTML 인라인 로딩 셸, 압축 JS 1MB 이하 목표.
- 왜: 산사(3초 입장, 이름 자동 생성), 담타(로그인 없이 닉네임 부여), ZEP(URL 클릭만으로 접속)가 모두 같은 구조다. 유입의 대부분이 인스타그램·스레드·카카오톡 **인앱 브라우저**에서 올 것이다.
- 주의: 인앱 브라우저의 WebGL 성능과 `navigator.share` 지원 여부는 **확인 못함**. 출시 전 실기기 테스트 필수(인스타그램, 스레드, 카카오톡 x iOS, Android).

**2. 9:16 "교주 임명장" 공유 카드 (M / 5)**
- 무엇: 랭크 승급 시 세로 이미지 1장을 만든다. 내 캐릭터 + 닉네임 + 교단명 + 직급 + 발급번호 + 희귀도 한 줄. 상세는 5장.

- 주의: "임명장 밈" 자체가 유행한다는 직접 근거는 **확인 못함**. 형식의 효과는 유사 사례에서 추론한 것이다.

**3. 초대 링크 = 포교 (M / 5)**
- 무엇: "포교 링크 복사" 버튼. 링크를 연 친구는 **같은 방, 초대한 사람 바로 앞**에 떨어지고 "○○님이 당신을 라면교로 포교 중입니다. [따라간다] [정중히 거절]" 카드를 본다. 수락하면 콩가라인에 자동 합류. 거절하면 초대한 쪽에 거절 멘트가 뜬다(거절도 웃기게).

- 주의: 브라우저 저장소는 지워질 수 있다. "기기 변경 시 사라짐"을 숨기지 말고, 필요하면 복구 코드(짧은 문자열)를 제공한다.

**14. 병맛 업적 + 거절 장면 "짤 저장" (S / 4)**
- 무엇: "10연속 거절: 철벽 수집가", "신도 0명으로 교단 창립" 같은 업적. 거절당한 순간을 자막 포함 정사각 이미지로 저장하는 버튼.
- 왜: Z세대가 가장 많이 공유하는 것이 "대화에서 답장 대신 쓸 수 있는 짤"이다. 실패가 웃긴 게임이 방송 클립을 만든다.

**15. 칭호 조합 (S / 3)**
- 무엇: "{수식어} {직급}" 조합. 예: "지하철 2번 출구의 길거리 전도사". 획득한 것 중 **표시할 칭호를 본인이 고른다.**
- 왜: 올해 밈의 공통점이 "남이 붙인 딱지가 아니라 스스로 고른 웃긴 타이틀"이다. 시스템이 일방적으로 놀리는 구조는 피한다.

**16. 플레이로만 얻는 코스메틱 (M / 3)**
- 무엇: 어깨띠, 확성기, 전단지 가방, 교단 색과 문양(프리셋 조합). 결제 없음.
- 왜: 아바타 꾸미기는 로블록스·제페토류의 기본 동기이고, 공유 카드에 내 캐릭터가 찍히므로 꾸밀 이유가 생긴다. 다만 한국 Z세대 대상 직접 수치는 **확인 못함**.

**17. 1:1 포교 배틀을 구경거리로 (L / 3)**
- 무엇: 20~30초 단판. 주변 NPC와 플레이어가 원을 만들어 구경하고 응원 이모트를 보낸다.
- 왜: 클립이 나오는 구조지만 구현량이 크다. 5번(군무)과 11번(시참)이 먼저다.

**18. 요일·시즌 한정 교단과 이벤트 (S / 3)**
- 무엇: 월요일엔 '월요병 구원회' 보너스, 수능·연말·새해 한정 칭호.
- 왜: 무한의 계단은 스킨과 보상을 주간 갱신한다. 부적도 월초에 공유가 몰린다. JSON 설정으로만 구현하면 싸다.

**19. 느슨한 연속 출석 "수행 N일차" (S / 3)**
- 무엇: 하루 1회 접속으로 카운트, 하루 빠져도 유지되는 안전망 1회.
- 왜: 듀오링고가 조건을 "하루 1회"로 단순화하고 안전망을 두어 리텐션을 올렸다. 다만 죄책감 유발 알림은 따라 하지 않는다. 피크민이 사랑받은 이유가 "경쟁·스트레스 없음"이었다.

**20. 교주와 1호 신도의 2인 인증 카드 (S / 3)**
- 무엇: 초대를 수락한 친구와 둘이 나오는 카드. "교주 ○○ / 1호 신도 △△".
- 왜: 텐션 케미 테스트처럼 둘이 찍히는 결과물은 서로 태그할 이유를 만든다. 상대 닉네임은 **상대가 수락했을 때만** 넣는다.

### 4.2 기능이 아닌 운영 훅 (별도)

- **만드는 과정을 스레드·X에 공개한다.** 산사는 개발자의 "제가 욕심이 과했네요" 같은 글과 방문자 수 공유 자체가 화제였다. 패치노트를 "교단 공지" 말투로 쓰면 그것도 콘텐츠다. (S / 4)
- **이름과 계정을 선점한다.** 산사는 이름을 도용한 밈코인이 나왔다. 도메인, 인스타그램·스레드·X 핸들을 먼저 잡고 "코인·토큰 없음"을 명시한다.

### 5.1 크기

| 스토리용 임명장·결산 카드 | **1080 x 1920 (9:16)** | 인스타그램 네이티브 공유 문서의 배경 이미지 최소 720x1280, 권장 9:16 [확인] |
| 링크 미리보기(OG) | 1200 x 630 | 산사도 이 크기. 용량은 300KB 이하 권장(산사는 839KB) [추론] |
| 짤(거절 장면) | 1080 x 1080 | 카카오톡·X·스레드에서 잘리지 않음 [추론] |
| 카카오톡 feed 템플릿 이미지 | 권장 크기 **확인 못함** | 업로드 최대 5MB, 카카오 서버 보관 100일 [확인] |

### 5.2 안전 영역 (1080 x 1920 기준)

- 일반 가이드: 상단 약 250px(프로필·이름), 하단 약 250px(답장 바)을 비운다. [요약]
- Meta 광고 사양을 인용한 도구들: 상단 14%(약 269px), 하단 35%(672px), 좌우 6%(약 65px). 광고 기준이라 일반 스토리에는 과하다. [요약, Meta 원문 미열람]
- **우리 규칙**: 핵심 텍스트(이름, 교단, 직급)는 x 80~1000, y 280~1480 안에 둔다. y 1480~1920은 작은 푸터와 여백으로 두어, 사용자가 **링크 스티커를 붙일 자리**로 남긴다. 스토리 이미지는 클릭이 안 되므로 짧은 주소를 글자로도 넣는다.

### 5.3 구성 요소 (위에서 아래로)

| y 범위 | 요소 | 내용 |
|---|---|---|
| 280~400 | 제목 | "교주 임명장" (명조·궁서 계열, 자간 넓게) |
| 400~450 | 발급번호 | "제 2026-000412 호" (전 서버 누적 발급 순번) |
| 470~1000 | 캐릭터 | **내 캐릭터 실제 렌더**(코스메틱 반영) + 뒤에 신도 줄. 고정 일러스트 금지 |
| 1020~1110 | 이름 | 닉네임, 가장 큰 글씨 |
| 1120~1190 | 소속·직급 | "라면교 신흥 교단장" |
| 1210~1380 | 본문 | 공문서체 2~3줄 (아래 예시) |
| 1390~1470 | 기록 + 희귀도 | "신도 12명 · 거절 39회" / "오늘 접속자 중 상위 3%" |
| 1280~1480 우측 | 직인 | 붉은 도장, 글자는 **"효력 없음"** 또는 "농담임" |
| 1500~1600 | 푸터 | 게임 이름 + 짧은 주소 + "실제 종교·단체와 무관한 농담입니다" |

개인화 요소는 최소 3개(닉네임, 교단명, 기록)가 들어가야 "내 것"으로 보인다. [추론, 'OO적 사고' 사례 기반]

### 5.4 문구 톤

원칙: **공문서의 진지한 말투 + 하찮은 내용.** 10월 밈 "부라는 게 숨긴다고 숨겨지는 것도 아니고"가 정확히 이 구조(과장된 자랑 + 진지한 말투)였다.

- 본문 예시 (잘한 경우): "위 사람은 길에서 47명에게 말을 걸어 39번 거절당하고도 굴하지 않았으므로, 이에 신흥 교단장으로 임명함."
- 본문 예시 (못한 경우): "위 사람은 신도 0명으로 교단을 창립하는 용기를 보였으므로, 이를 딱하게 여겨 임명함."
- 희귀도는 **기분 좋은 숫자일 때만** 백분위를 쓴다. 하위권이면 "꾸준함 부문 1위"처럼 다른 축으로 바꾼다.
- 과장 숫자 허용: "전단지 54,000장을 뿌린 것으로 추정됨."
- 금지: 감성 문구, 이모지 남발, 농담을 설명하는 문장, "~한 이유" 같은 낚시형 제목.

### 5.5 구현 메모

- 인스타그램 "스토리에 공유"의 공식 연동은 **iOS·Android 네이티브 앱 전용**이다(URL 스킴 `instagram-stories://share`, Android 인텐트, Facebook App ID 필요). 웹에는 공식 경로가 없다. [확인: Meta 문서]
- 따라서 웹에서는 **Web Share API의 파일 공유 → OS 공유 시트 → 인스타그램**이 최선이다. `navigator.share`의 `files`는 iOS Safari 14+와 Android Chrome에서 지원, Firefox는 미지원. [요약: caniuse]
- 사용자 제스처 안에서 호출해야 한다. 카드 이미지를 **모달을 열 때 미리 만들어 두고**, 버튼 탭에서는 곧바로 `share`만 부른다(탭 뒤에 비동기 렌더를 기다리면 제스처가 만료될 수 있음. 실기기 검증 필요). [추론]

```ts
// 카드 모달이 열릴 때 blob을 미리 만들어 둔다
let cardBlob: Blob | null = null;

async function prepareCard(canvas: HTMLCanvasElement) {
  await document.fonts.ready; // 폰트 로드 전 그리면 기본 글꼴로 찍힘
  cardBlob = await new Promise<Blob | null>((ok) => canvas.toBlob(ok, 'image/png'));
}

// 버튼 클릭 핸들러: 여기서는 기다릴 일을 만들지 않는다
async function onShareTap(inviteUrl: string) {
  if (!cardBlob) return showSaveFallback();
  const file = new File([cardBlob], 'gyoju-certificate.png', { type: 'image/png' });
  const data: ShareData = { files: [file], text: `나 방금 교주 됨 ${inviteUrl}` };
  if (navigator.canShare?.(data)) {
    try { await navigator.share(data); return; }
    catch (e) { if ((e as DOMException).name === 'AbortError') return; }
  }
  showSaveFallback(); // <img>로 띄워 길게 눌러 저장 + 다운로드 버튼 + 링크 복사
}
```

- 폴백은 반드시 필요하다. 인스타그램·카카오톡 인앱 브라우저에서 파일 공유가 되는지는 **확인 못함**. 이미지를 `<img>`로 보여 주고 "길게 눌러 저장"을 안내한다.
- 데스크톱은 다운로드 버튼 + 이미지 클립보드 복사(`ClipboardItem`)를 준다.
- "그래픽은 전부 절차 생성, 에셋 파일 없음" 원칙과 한글 명조 글꼴이 충돌할 수 있다. 시스템 글꼴 폴백(`"AppleMyungjo", "Nanum Myeongjo", "Batang", serif`)은 안드로이드에서 고딕으로 떨어질 가능성이 크다. 카드 전용 서브셋 웹폰트를 **카드 모달을 열 때만** 지연 로드하는 안을 검토한다. [추론]

## 6. 이름과 말투 가이드

### 6.1 해도 되는 것

| 원칙 | 설명 | 예시 |
|---|---|---|
| 일상의 사소한 것을 숭배 대상으로 | 누구나 아는 생활 소재 | 라면교, 퇴근을 믿는 사람들, 월요병 구원회, 칼퇴 수호단, 이불 밖은 위험해 연합, 주말 대기 연합, 택배 도착 기원회, 배터리 1% 구원회, 알람 5분만 더 회, 낮잠 연구회 |

| 엉성한 연기 | 드라마피케이션. 한두 줄 대사, 10초 | 단상에서 과하게 비장한 계시 낭독 후 머쓱한 동작 |
| 반말과 해요체 혼용 | 스레드의 반말 문화와 맞음 | "교주 됐어. 어쩌다 보니." |
| 내부 분파 농담 | 무해한 취향 대립 | 라면교: 꼬들파 vs 퍼진파, 붕어빵: 팥 vs 슈크림 |

NPC 거절 멘트 예시(전부 엉뚱한 방향으로 꺾는다)
- "제가 지금 라면 물 올려놓고 나와서요."
- "도는 모르는데 도보 12분은 압니다."
- "저희 집은 대대로 퇴근교입니다."
- "인상이 좋다는 말, 오늘 세 번째 듣는데 다 다른 교단이네요."

교단 이름을 지을 때의 추가 규칙 [추론]
- '교, 교주, 신도, 포교'는 게임의 전제라 쓰되, **실존 교단 이름에 들어가는 고유 단어**는 조합기 단어 목록에서 뺀다.
- 숭배 대상은 사람이 아니라 사물·상황으로 한다(라면, 퇴근, 주말). 실존 인물·연예인·정치인은 대상이 될 수 없다.
- 이름만 들어도 무해함이 드러나야 한다. 설명이 필요한 이름은 버린다.

### 6.2 하면 안 되는 것 (오글거림)

| 피할 것 | 이유 |
|---|---|

| "MZ", "인싸", "핵~", "실화냐" 류 | 기성세대가 젊은 척하는 말로 읽힘 [추론] |
| 농담 설명하기, 느낌표·이모지 과다 | 최고심 부적 사례: 논리적 설명을 붙이면 공감이 깨짐 |
| 시스템이 플레이어를 일방적으로 조롱 | 자조는 본인이 고를 때만 웃김. 칭호는 선택형으로 |

## 8. 우리 게임에 적용할 것

### 8.1 출시 전 필수 (MVP)

1. 링크를 열면 3초 안에 거리 위에 선다. 가입·닉네임 입력 없음. 자동 닉네임. HTML 인라인 로딩 셸.
2. 초기 JS 압축 1MB 이하를 예산으로 잡는다(산사 약 0.7MB).
3. OG 태그 3종을 "친구에게 보낼 문장"으로 작성. OG 이미지 1200x630, 300KB 이하.
4. 초대 링크 = 포교. 같은 방, 초대자 앞에 스폰. 수락/거절 카드.
5. 콩가라인 + 줄 전체가 따라 하는 이모트 3종 이상.
6. 자유 채팅 없음. 프리셋 말풍선과 예능 자막.
7. 임명장 카드(1080x1920) + Web Share 파일 공유 + 저장 폴백.
8. 첫 화면과 카드에 허구·풍자 고지. 실제 종교 용어·상징 금칙 목록을 코드 리뷰 체크리스트에 넣는다.
9. 방 자동 증설과 대기열 화면. 방당 정원·맵 크기·동기화 범위를 원격 설정으로 조절 가능하게.
10. 인스타그램·스레드·카카오톡 인앱 브라우저 x iOS·Android 실기기 테스트(WebGL 성능, 공유, 이미지 저장).

### 8.2 출시 후 1~2주

11. 세션 결산 카드 + 교주 유형.
12. 오늘의 계시(일일, 시드 기반).
13. 방 실시간 랭킹 + 오늘의 전국 랭킹(자정 KST 초기화) + 교단 대항전.
14. 병맛 업적과 "짤 저장".
15. 스트리머 모드(방 코드 가리기, 시참 교대 대기열).
16. 정시 대집회(낮 12:30, 밤 21:00 등 심야 제외).

### 8.3 지표를 보고 결정

17. 도감 3종, 칭호 조합, 코스메틱.
18. 1:1 배틀 관전 연출.
19. 시즌·요일 이벤트, 느슨한 출석.
