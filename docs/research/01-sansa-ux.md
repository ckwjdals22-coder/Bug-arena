# 01. 레퍼런스 UX 분해: 온라인 절 "산사" (sansatemple.com)

- 조사일: 2026-11-26 (KST 14:40 전후 실측)
- 목적: "도를 아십니까? — 교주 시뮬레이터"의 진입 흐름 · 카메라 · 조작 · 방 모델을 **가볍고 직관적으로** 만들기 위한 UX 원칙 추출
- 범위 제한: 산사는 **단순함/가벼움의 참고 사례**일 뿐이다. 그림체, 동자승 캐릭터, 사찰 미술, 문구, 코드는 가져오지 않는다. 이 문서의 코드 조각은 전부 우리 게임용으로 새로 쓴 것이다.

## 1. 한눈에 보는 결론

1. **링크를 누르면 탭 0번으로 세계 안에 서 있다.** 닉네임 입력, 아바타 선택, 약관, 로그인, "시작" 버튼이 전부 없다. 서버가 별명을 붙여 준다("고요한 구름", "느긋한 물결", "푸른 솔잎" — 접속할 때마다 달랐다). [실측]
2. **화면에 상시 보이는 동작 버튼은 4개뿐이다** (합장 · 절하기 · 목탁 · 염주). 하단 알약 모양 바 하나. 조이스틱 없음. [실측]
3. **이동은 "바닥을 누르면 거기까지 걸어감"**, 시점은 한 손가락 드래그, 확대는 두 손가락. PC는 클릭 이동 + WASD/방향키 + 휠. [실측]
4. **채팅이 없다.** 소통 수단은 동작(합장하면 주변이 따라 합장)뿐이고, 자유 입력은 40자 소원 한 줄 정도로 제한된다. 욕설·정치·모더레이션 비용이 통째로 사라진다. [실측+보도]
5. **방은 "산사 서버 N" 목록**이고 기본값은 `room=auto`(서버가 배정). 조사 시점 정책은 **10개 방 × 50명 = 500명**. 한때 100개 × 100명 = 1만 명까지 늘렸었다. [실측+보도]
6. **기술 스택은 우리와 거의 같다**: three.js r180 + Vite 번들 + 순수 WebSocket + Cloudflare. React/react-three-fiber/Babylon/PlayCanvas/socket.io/Colyseus/PartyKit 흔적 없음. [실측]
7. **가장 큰 교훈은 운영 쪽에 있다**: 방석 20개로 열었다가 다음 날 서버가 죽었고, 한 달 뒤 조사 시점 동시 접속은 10개 방 합계 77명이었다(10/30 18시 보도 수치 5,119명). 폭발과 식는 속도 둘 다 대비해야 한다. [보도+실측]

### 2.3 진입 흐름 [실측]

```
링크 탭
  └─ (0.0s) HTML 9.7KB 도착 → 인라인 CSS만으로 부트 화면 즉시 표시
        "산사 / 산사에 들어갈 준비를 하고 있어요." + 5단계 진행 막대
  └─ (~3s*)  상단·하단 HUD가 이미 붙음. 로딩 문구가 단계별로 바뀜
        "청연당과 입구 돌길을 준비하고 있어요." → "입구의 첫 화면을 그리고 있어요."
  └─ (~5s*)  WebSocket 연결(room=auto) → 스냅샷 수신 → "산사에 도착했어요."
  └─ 산문(입구) 앞에 서 있음. 정면에 돌길과 법당이 보임. 머리 위 "나 · 고요한 구름"
```
(*) 헤드리스 소프트웨어 렌더링 기준. 캔버스가 스스로 기록한 값은 첫 렌더 2.7s, 준비 완료 5.9s. 트렌디움 뉴스레터는 "3초 만에 입장"이라고 썼다 [보도].

- **필수 탭 수: 0.** 닉네임 · 아바타 · 약관 · 로그인 · 시작 버튼 없음.
- 별명은 서버가 부여. "형용사 + 자연물" 조합(다정한 이끼, 작은 솔잎, 잔잔한 물결, 고요한 구름…). 바꾸는 UI 없음.
- 소리는 **꺼진 채 시작**. 우상단 스피커 버튼 또는 "염불 듣기" 칩을 눌러야 켜진다. 첫 터치/키 입력 때 오디오를 푼다.
- 로딩이 길어질 때의 장치:
  - 15초가 지나면 "다시 들어가기" 링크가 **CSS 애니메이션만으로** 나타남(JS가 죽어도 동작).
  - 로딩 화면에 "염주 먼저 굴리기" 버튼 — 3D가 준비되기 전에 혼자 할 수 있는 것을 먼저 준다.
  - 방이 가득 차면 "입장 대기 중 · 염주는 바로 쓸 수 있어요". 대기 재시도 8~12초 간격.
- 나가기 버튼(좌상단) → "편안히 쉬어 가셨나요 / 다시 머무르기" 한 장으로 끝. 소리와 연결을 모두 정리.
- 30분 안에 돌아오면 같은 방문으로 이어 준다(위치 · 절 횟수 복구). 토큰은 `sessionStorage`.
- 탭을 여러 개 열면 한 탭만 활성("다른 탭에서는 잠시 쉬고 있어요"). `navigator.locks` 사용.

### 2.4 화면 구성 (모바일 390×664 CSS px 기준) [실측]

```
┌──────────────────────────────────────────┐
│ (←나가기)(지도)(산사 01 ▾)   (🍚)(🔇)(설정) │  ← 알약 2개, 버튼 각 44×44
│                               [염불 듣기] │  ← 맥락 칩
│      눌러 이동 · 쓸어 둘러보기 · …        │  ← 한 줄 힌트 (입력 장치별로 문구 다름)
│                                          │
│              (3D 세계)                    │
│                                          │
│              [나 · 고요한 구름]           │  ← 내 이름표만 상시 표시
│                 (캐릭터)                  │  ← 화면 세로 55~75% 지점
│                                          │
│  ( 합장 )( 절하기 )( 목탁 )( 염주 )       │  ← 하단 알약, 버튼 각 87×54
└──────────────────────────────────────────┘
```

- 상단 좌: 나가기 · 지도 · **방 선택(현재 방 번호 표시)**. 상단 우: 후원 · 소리 · 설정. 그게 전부.
- 반투명 유리 질감 알약(HUD가 3D를 가리지 않음). 모든 터치 대상이 44px 이상.
- 데스크톱도 **같은 배치**. 하단 버튼에 `<kbd>` 단축키 표기(1 절하기, 2 염주, 3 합장, 5 목탁, E/Space 절하기).
- 맥락 버튼은 가까이 갔을 때만 하단 바 위에 뜬다("탑돌이 시작", "범종 치기", 연등 안내 등).
- 버튼은 **자기 자신의 취소 버튼으로 변한다**: "절하기" → 누르면 "멈추기", "합장" → "합장 중".
- 실패 안내는 다음 행동을 알려 주는 한 줄 토스트: "가까운 빈 바닥을 눌러주세요".

### 2.5 카메라 [실측]

| 항목 | 값 |
|---|---|
| 방식 | **3인칭 추적 궤도 카메라** (캐릭터 뒤에서 따라감. 고정 각도 아님) |
| 화각 | 64° (near 0.08, far 280), 안개 95~232 |
| 진입 시 기본값 | 거리 7.5, 피치 0.18 rad(약 10°) |
| 좌우(요) | 드래그 1px당 0.0034 rad, 제한 없음 (390px 한 번 쓸면 약 76°) |
| 상하(피치) | 드래그 1px당 0.0022 rad, **−0.24 ~ +0.31 rad로 좁게 제한** (앉았을 때만 −0.12 ~ 1.12) |
| 확대/축소 | 거리 2.2 ~ 14. 핀치 또는 휠(지수 스케일) |
| 자동 시선 | 자동 보행 중에는 카메라가 진행 방향으로 천천히 돌아감(최대 약 1.35 rad/s). 손으로 드래그한 뒤 2.5초 동안과 터치 중에는 멈춤 |
| 진입 구도 | 입구 문 앞에서 **목적지(법당)가 정면에 보이게** 스폰 |

피치를 좁게 묶은 게 핵심이다. 사용자가 땅속이나 하늘을 보다가 길을 잃을 일이 없다.

### 2.6 조작 [실측]

| | 모바일 | PC |
|---|---|---|
| 이동 | **바닥 탭 → 그곳까지 자동 보행**(경로 탐색 워커, 목적지 마커) | 바닥 클릭, WASD, 방향키 |
| 시점 | 한 손가락 드래그 | 마우스 드래그 |
| 확대 | 두 손가락 핀치 | 휠 |
| 상호작용 | 사물/사람을 직접 탭 (향로, 종, 의자, 커피 머신, 연등 고리) | 클릭(호버 시 커서 변경) |
| 동작 | 하단 4버튼 | 하단 4버튼 + 숫자키 |
| 조이스틱 | **없음** | — |

- 걷는 속도 2.405 유닛/초. 느리다(쉬는 곳이라 의도적).
- **한 번 누르면 알아서 한다**: "절하기"를 누르면 빈 방석을 찾아 걸어가서 앉고 절을 시작한다. 방석이 없으면 "빈 방석을 찾지 못했어요. 둘러보다 다시 눌러주세요."
- 키보드로 움직이면 진행 중이던 자동 보행 · 대기 · 인사가 취소된다(입력이 항상 자동 동작을 이긴다).
- 힌트 한 줄은 입력 장치에 따라 다르다: 터치 "눌러 이동 · 쓸어 둘러보기 · 두 손가락 확대/축소" / 마우스 "바닥 클릭 · 드래그로 둘러보기 · 휠로 확대/축소".

한 달 사이 추가된 것 [실측]: 지도, 소원 연등(40자, 같은 방에 공개), 향 올리기(대기 줄 있음), 탑돌이, 범종, 기와 나르기, 의자에 앉아 쉬기 + 사진 저장, 감 따먹기, 춤, 브랜드 협업 구역 2곳(편의점 커피 브랜드의 가상 커피 내리기/건네기, 음원 서비스의 음악 기록 남기기).

눈여겨볼 상호작용 설계:
- **플레이어 간 요청-수락 카드**: 가까운 사람에게 "커피 요청하기" → 상대에게 "{이름}님의 커피 요청 [건네기][거절]" → 서로 걸어가서 건넴. 시간 초과 · 거리 · 상대가 바쁨 등 실패 사유가 전부 문구로 준비돼 있다. (우리 "교단 초대 수락/거절 카드"와 같은 구조)
- **조건부 보상**: "절 25번을 마치면 마실 수 있어요" — 0/25 진행 막대가 하단 바 위에 뜬다.
- **순서 대기**: 향로는 한 명씩. "앞에 N명이 있어요 · 차례가 되면 다가갑니다".

### 2.8 다른 사용자가 보이는 방식 [실측]

- 모두 **같은 모습의 캐릭터**. 꾸미기 없음(색상 필드는 있으나 눈에 띄는 차이 없음).
- **남의 이름표는 숨김이 기본.** 캐릭터를 탭하거나 마우스를 올리면 3초만 보인다. 내 이름표("나 · 별명")만 상시.
- 방문객 목록 창이 따로 있다("N명 함께 있는 중").
- 원격 캐릭터는 저해상도 모델(149 KB)을 **GPU 인스턴싱**으로 한 번에 그린다. 관찰 시 원격 44명 중 화면에 보이는 것 35명, 인스턴스 30개, 나머지는 "휴면" 처리.
- 동작(합장, 절, 염주)은 이벤트로 중계되어 다른 사람 화면에서도 재생된다. 한 명이 합장하면 주변이 따라 하는 광경이 생긴다 [보도].

### 2.9 방/채널 모델 [실측]

공개 방 목록 API(`GET /api/rooms/village`) 응답 요약 (2026-11-26 14:39 KST):

```json
{
  "rooms": [
    {"id":"maru",    "number":1, "capacity":50, "count":50},
    {"id":"maru-02", "number":2, "capacity":50, "count":15},
    {"id":"maru-03", "number":3, "capacity":50, "count":3}
    // … 4~10번: 0, 1, 1, 2, 2, 2, 1
  ],
  "roomPolicy": {"revision":"rooms-10-20261114","roomCapacity":50,"totalCapacity":500,"regions":["apac"]},
  "worldMap": {"sha256":"…","bytes":25685}, "serverTime": 1795671587226
}
```

- 기본 입장은 `room=auto` → 서버가 방을 정해 준다. 관찰 3회 모두 1번 방에 들어갔다(49~50/50). 분포(50/15/3/0/1/1/2/2/2/1)로 볼 때 **앞번호부터 채우는 방식 [추정]**.
- 좌상단 "산사 01 ▾"를 누르면 방 목록(번호, `n / 50명`, 현재 방 표시, 새로고침, 방문객 보기). 목록 수치에는 "N초 전" 신선도 표시가 붙는다.
- URL `?room=<id>` 로 특정 방 직행 가능.
- 방이 가득 차면 연결 상태 줄에 "이 서버가 가득 찼어요. 다른 서버를 골라주세요" + [서버 선택] 버튼.
- **방 이동은 새 소켓을 먼저 열고 스냅샷을 받은 뒤 옛 소켓을 닫는다**(끊김 없는 전환). 8초 안에 안 되면 원래 방 유지.
- 클라이언트가 지원하는 상한은 방 100개 × 방당 100명. 실제 값은 서버 정책(revision 문자열)으로 내려온다 → **코드 배포 없이 방 수와 정원을 바꾼다.**
- 맵 데이터는 sha256으로 버전 관리되는 25 KB JSON. 스냅샷에 맵 버전이 들어 있고, 다르면 "새 풍경이 준비됐어요. 다시 들어와주세요".

### 2.10 네트워크 프로토콜 [실측]

| 방향 | 내용 |
|---|---|
| 접속 | 쿼리에 `room, protocol=2, wire=3, resume=1, interest=1, …` |
| 서버→클라 첫 프레임 | JSON `snapshot` 1개. 43명일 때 12.3 KB (1인당 약 290 B). 필드: id, name, seat, cushion, color, joinedAt, pose, position, dance, bowAt |
| 서버→클라 이동 | **바이너리 델타**. 헤더 28 B + 새 프로필 JSON + 1인당 30 B(좌석 u16, 방석 i16, 포즈 u8, 플래그 u8, x/z/yaw f64×3) |
| 서버→클라 동작 | JSON `event`(합장 · 절 · 염주 등), 좌석 승인/거절, 위치 보정(`position-corrected`) |
| 클라→서버 이동 | JSON `{type:"move", x, z, yaw, pose}`. **값이 안 바뀌면 안 보냄.** 최소 간격 100 ms(특정 모드 500 ms) |
| 흐름 제어 | 클라가 0.5초마다 `ack`(받은 revision). 64 KB 넘으면 즉시 |
| 생존 확인 | 60초 무활동 시 ping, 20초 안에 응답 없으면 끊고 재접속 |
| 재접속 | 지수 백오프 `min(15s, 0.7s × 2^n) + 0~0.35s 지터` |
| 관심 영역 | 클라가 `interest` 범위를 보내고 서버가 수락/거절 |
| 유휴 절전 | 입구에서 오래 가만히 있으면 서버가 연결을 끊고 "잠깐 쉬고 있어요 [여기서 계속 쉬기]" |

50명 방에서 가만히 서서 받은 양(17.5초 관찰): 바이너리 델타 471개(초당 약 27개, 평균 89 B), 전체 하향 약 **4.6 KB/s**. 고정 틱이 아니라 누가 움직일 때마다 작은 델타를 흘려보내는 방식 [추정].

### 2.11 성능/배터리 장치 [실측]

- `devicePixelRatio` 상한: 폭 700px 미만 1.6, 그 이상 1.75.
- **가변 프레임**: 모바일(폭 700px 미만 또는 터치 기기)은 **최대 30fps**, 데스크톱은 최대 60fps. 입력 후 0.45초 동안과 움직이는 중이 아니면 30fps(조건에 따라 15fps)로 낮춘다.
- 그림자 맵 자동 갱신 끔(정적 그림자). 그림자 맵 모바일 2048 / 데스크톱 3072.
- 장면을 165개 청크로 나누고 안 보이는 청크는 재움(관찰 시 103 활성 / 62 휴면).
- 탭이 숨겨지면 렌더와 소리 정지(설정에서 백그라운드 재생만 선택 가능).
- 이름표는 3D 텍스트가 아니라 DOM 오버레이. 그리는 것은 내 것 + 방금 탭한 한 명뿐.

### 2.12 공유 장치 [실측]

- 브랜드 협업 "커피 배달 카드": **1080×1440 PNG**를 캔버스로 생성. 상단 1080×1080 그림, 큰 한 줄 문구, 사용자가 쓰는 한마디(선택, 3줄 넘으면 글자 크기를 30→24px로 줄임), **초대 링크 QR 코드**, 로고.

## 4. 가볍고 직관적으로 느껴지는 UX 원칙

1. **입장이 곧 첫 화면이다.** 랜딩 페이지와 게임 사이에 아무것도 없다.
2. **결정을 뒤로 미룬다.** 이름도 방도 서버가 정하고, 바꾸고 싶은 사람만 나중에 바꾼다.
3. **동사는 4개 이하.** 나머지는 그 장소에 갔을 때만 나타난다.
4. **한 번 누르면 끝까지 해 준다.** "절하기" = 자리 찾기 + 걸어가기 + 앉기 + 절.
5. **버튼이 자기 상태를 말한다.** 절하기 ↔ 멈추기. 모드 표시등을 따로 두지 않는다.
6. **입력이 자동 동작을 항상 이긴다.** 손대면 자동 보행 · 자동 시선이 즉시 멈춘다.
7. **카메라가 길을 잃지 못하게 묶는다.** 좌우는 자유, 상하는 좁게, 거리는 범위 제한.
8. **스폰 지점에서 목적지가 정면에 보인다.** 튜토리얼 대신 구도가 안내한다.
9. **힌트는 한 줄, 장치에 맞게.** 모달 튜토리얼 없음.
10. **기다림에 할 일을 준다.** 로딩 · 대기 중에도 염주는 굴릴 수 있다.
11. **실패 문구는 다음 행동을 말한다.** "~하지 못했어요. ~해 주세요."
12. **남의 정보는 요청할 때만.** 이름표 숨김 → 화면이 깨끗하고 그리기도 싸다.
13. **말 대신 동작으로 소통.** 모더레이션 비용 0, 그런데도 "같이 있다"는 느낌은 남는다.
14. **가만히 있으면 싸진다.** 30fps 절전, 숨은 탭 정지, 유휴 연결 해제.
15. **방 정원과 맵은 데이터다.** 코드 배포 없이 운영 중에 바꾼다.
16. **문구 톤이 일관된다.** 전부 "~해요" 체, 짧고 다정함. 오류조차 세계관 안의 말투.

## 5. 우리가 따를 원칙 / 따르지 않을 것

### 원칙으로 가져갈 것

| 산사의 원칙 | 우리 게임에서의 형태 (우리 고유 표현) |
|---|---|
| 탭 0 입장 + 자동 별명 | 링크 → 바로 지하철 출구 앞. 별명은 "수상한/배고픈/졸린 + 행인/구도자" 같은 **우리 식 풍자 조합** |
| 동사 4개 이하 | 말 걸기 · 설교 · 감정표현 · 내 교단. 연단/천막/헌금함은 가까이 갔을 때만 |
| 원탭 자동 수행 | "말 걸기" = 가장 가까운 시민에게 걸어가서 멘트 카드 3장 열기 |
| 버튼이 상태를 말함 | 설교 ↔ 설교 끝내기, 배틀 신청 ↔ 신청 취소 |
| 좁게 묶은 3인칭 카메라 | 아래 7.2절 |
| 한 줄 힌트 | 첫 포교 성공 전까지만 표시 |
| 남 이름표 숨김 | 탭/호버 시 3초 + 상호작용 중인 상대만 |
| 요청-수락 카드 | 교단 초대, 1:1 포교 배틀 신청에 그대로 맞는 구조(거리 · 시간 초과 · 상대 바쁨 사유 포함) |
| 순서 대기 UI | 연단("오늘의 계시")은 한 명씩. "앞에 N명" |
| 조건부 진행 막대 | 직급 승급까지 "신도 3/5명" 막대를 하단 바 위에 |
| 채팅 없음 | 자유 채팅은 넣지 않는다. 멘트는 전부 선택지. 교단 이름도 조합식 |
| 공유 이미지 사전 생성 + 3버튼 | 교주 임명장 (아래 7.5절) |
| 방 목록 + auto 배정 + `?room=` | 아래 7.4절 |
| 가변 프레임, DPR 상한, 인스턴싱 | 그대로 적용. 우리는 NPC 군중이 있어 더 중요 |

### 가져오지 않을 것

- 동자승 · 사찰 · 불상 등 **캐릭터와 미술 일체**, "형용사 + 자연물" 별명 어휘, 문구, 음원, 코드.
- **느린 템포.** 산사의 목표는 "아무 감정도 안 느끼기"이고 우리는 웃기는 게임이다. 걷는 속도 · 반응 · 연출은 훨씬 빨라야 한다.
- **조이스틱 없는 조작.** 우리는 NPC를 쫓아다녀야 하므로 프로젝트 방침대로 가상 조이스틱을 둔다(단, 탭 이동을 병행).
- **후원/송금 링크.** 우리는 실제 돈을 다루지 않는다. 헌금함은 가짜 아이템만.
- **실제 종교 요소.** 산사는 종교 의례를 진지하게 다뤄 호감을 얻었다. 우리는 풍자이므로 실제 종교 · 단체 · 인물 연상을 반대로 철저히 피해야 한다.
- **브랜드 협업으로 불어난 기능들.** 한 달 만에 게임 JS 1.85 MB, 개인정보 안내문 수천 자가 됐다 [실측]. 핵심 루프 밖 기능은 지연 로딩하고 초기 번들 예산을 지킨다.

## 7. 우리 게임에 적용할 것

### 7.1 진입 흐름

목표: **링크 탭 → 3초 안에 조작 가능, 15초 안에 첫 포교 결과, 필수 탭 0번.**

```
0.0s  HTML(≤14KB, 부트 화면 CSS 인라인) — "○번 출구로 나가는 중…" + 단계 진행 막대
~1.5s 절차적 거리 생성 + 렌더 시작. HUD는 로딩 중에 미리 붙임
~2.5s WS 연결(room=auto) → 스냅샷 → 지하철 출구 앞 스폰. 정면에 광장과 시민들
      머리 위 [나 · 졸린 행인 27], 힌트 한 줄
      하단에 강조된 버튼 하나: "말 걸기"
탭 1   가장 가까운 시민에게 자동으로 걸어감 → 멘트 카드 3장
탭 2   결과 연출(입교/도망/거절 대사) → 직급 진행 막대 등장
```

- 닉네임 입력 · 아바타 선택 · 약관 모달 · 시작 버튼을 만들지 않는다. 별명 변경과 교단 창설은 **나중에, 원하는 사람만**.
- 별명은 서버가 부여(중복 방지용 숫자 2자리). 어휘는 우리 세계관으로 새로 짠다.
- 로딩이 10초를 넘기면 CSS만으로 "다시 시도" 링크 노출. 15초 넘으면 오류 문구.
- 대기열이 생기면 **대기 중에도 놀 수 있게**: 혼자 하는 "멘트 연습"(로컬 NPC 1명)을 먼저 띄운다.
- 소리는 꺼진 채 시작하되 음소거 아이콘을 눈에 띄게. 첫 입력에서 AudioContext 해제.
- 풍자 고지("모든 내용은 가상이며 실제 종교 · 단체와 무관합니다")는 모달이 아니라 부트 화면 하단과 설정에 상시 문구로.
- 나가기 화면 = 임명장 공유 제안 + "다시 포교하러 가기".
- 30분 이내 재접속은 같은 캐릭터로 복구(토큰은 `sessionStorage`, 개인정보 아님).

초기 전송 예산(제안): HTML+CSS ≤ 30 KB, JS ≤ 350 KB(압축 전송 기준, three.js 포함), 폰트는 시스템 폰트 우선. 산사는 진입+게임 번들 두 개만 합쳐 약 676 KB를 전송했다 [실측].

### 7.3 조작

모바일:
- **왼쪽 절반 터치 시작 = 떠다니는 조이스틱**(엄지 닿은 곳에 생성). 프로젝트 방침 유지.
- **오른쪽 절반 드래그 = 시점**, 두 손가락 = 확대.
- **짧은 탭(이동 8px 미만, 250ms 미만) = 그곳으로 이동 / 시민 탭 = 다가가서 말 걸기.** 산사식 한 손 조작을 조이스틱과 함께 제공.
- 우하단 큰 **맥락 버튼 1개(64px)**: 근처 대상에 따라 "말 걸기 / 연단 오르기 / 헌금함 보기 / 배틀 신청"으로 바뀜.
- 하단 알약 바는 4칸 이하. 터치 대상 최소 44px, 주요 버튼 54px 이상.

PC:
- WASD/방향키 + 클릭 이동 + 드래그 시점 + 휠.
- E/Space = 맥락 행동, 숫자 1~4 = 하단 바, Esc = 닫기/취소. 버튼에 `<kbd>` 표기.

공통:
- 이동 입력이 들어오면 자동 보행 · 대기 · 카드 선택 대기를 취소.
- 토글 버튼은 라벨이 취소 동작으로 바뀜.
- 힌트는 `pointerType`으로 문구를 갈아 끼움.
- 실패 토스트는 "무엇이 안 됐는지 + 다음에 할 일" 한 줄.
- 멘트 카드는 큰 버튼 3장, 엄지 닿는 하단에. 5초 안 고르면 닫지 말고 그대로 둠(급하게 만들지 않기).

### 7.5 공유 이미지 (교주 임명장)

산사의 카드는 1080×1440이었다(메신저 공유용). 우리는 인스타 스토리용이므로 **1080×1920(9:16)**. 상하 스토리 UI 영역은 비워 둘 것(안전 영역 수치는 별도 리서치 필요 — 이 조사에서는 확인 못함).

가져올 구조:
1. 결과 화면을 여는 순간 **캔버스를 미리 그려 Blob을 만들어 둔다.** 버튼을 누른 뒤 만들기 시작하면 사용자 제스처가 소진되어 공유 시트가 안 열릴 수 있다.
2. 버튼 3개: 공유 · 복사 · 저장.
3. 카드 구성: 별명 + 직급 + 숫자(신도 수, 헌금함의 황당한 품목) + 선택 한마디 + **`?room=` 딥링크 QR** + "가상 풍자 게임" 문구.
4. 실패 시 문구로 우회로 안내("저장한 뒤 스토리에 사진으로 올려 주세요").

```ts
// 우리 게임용으로 새로 쓴 예시
export type ShareResult = 'shared' | 'cancelled' | 'downloaded';

/** blob은 결과 화면을 열 때 미리 만들어 둔다 (탭 순간에는 await 없이 share 호출) */
export async function shareCertificate(blob: Blob): Promise<ShareResult> {
  const file = new File([blob], '교주-임명장.png', { type: 'image/png' });
  if (navigator.canShare?.({ files: [file] })) {
    try {
      await navigator.share({ files: [file] });
      return 'shared';
    } catch (err) {
      if ((err as DOMException).name === 'AbortError') return 'cancelled';
      // 그 외 실패는 저장으로 내려감
    }
  }
  const url = URL.createObjectURL(blob);
  const a = Object.assign(document.createElement('a'), { href: url, download: file.name });
  a.click();
  setTimeout(() => URL.revokeObjectURL(url), 30_000);
  return 'downloaded';
}

export async function copyCertificate(blob: Blob): Promise<boolean> {
  try {
    await navigator.clipboard.write([new ClipboardItem({ 'image/png': blob })]);
    return true;
  } catch {
    return false; // "복사하지 못했어요. 저장한 뒤 올려 주세요."
  }
}
```

```ts
  private last = 0;
  constructor(private activeFps = 60, private idleFps = 30, private holdMs = 450) {}
  poke(now = performance.now()) { this.activeUntil = now + this.holdMs; }
  shouldRender(now: number, moving: boolean): boolean {
    const fps = moving || now < this.activeUntil ? this.activeFps : this.idleFps;
    if (now - this.last < 1000 / fps - 1) return false;
    this.last = now;
    return true;
  }
}
```

- 산사는 모바일을 30fps로 묶었다. 우리는 조이스틱으로 계속 움직이는 게임이라 모바일도 입력 중에는 60fps를 시도하되, 평균 프레임 시간이 20ms를 넘으면 30fps로 내리는 자동 강등을 둔다(실기기 검증 필요).
- 다른 플레이어 · NPC는 `InstancedMesh`로. 절차적 저폴리라 본 애니메이션 대신 정점 셰이더 흔들림으로 충분한지 먼저 검증.
- 그림자는 정적 1장 또는 캐릭터 발밑 원형 그림자.
- 이름표는 DOM 오버레이, 내 것 + 선택한 대상만.
- 숨은 탭은 렌더 · 소리 정지.

### 7.7 퍼지게 만드는 장치

- **찍히는 장면을 기본값으로**: 신도 줄(콩가 라인), 집단 설교 동시 동작. 똑같이 생긴 큰 머리 캐릭터 여럿이 같은 동작을 하는 화면이 산사에서 가장 많이 공유됐다.
- **자동 별명이 곧 캡처 거리**: 별명 + 직급 조합이 웃기도록 어휘를 설계.
- **실시간 숫자 공개**: 방 인원, 오늘 입교한 시민 수.
- **한 줄 소개**: "링크 누르면 바로 길거리 교주". 서론 금지.
- **공개 운영**: 서버가 터지면 숨기지 말고 세계관 말투로 공지("신도가 너무 몰려 본부가 무너졌습니다").
- 인스타 인앱 브라우저에서 열리므로 **인앱 브라우저 실기기 테스트를 출시 조건에 포함**(WebGL, 오디오 해제, 파일 공유 동작).
