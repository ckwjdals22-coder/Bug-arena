# 개선계획

기존 사이트 분석(`00`), 시장 조사(`01`), 아키텍처(`02`), 디자인 시스템(`03`), 디자인 리서치(`05`)를 바탕으로 정한 실행 계획입니다.
각 항목 끝의 기호는 조사 문서의 인사이트 번호입니다(예: CU-2 = 고객 2번).

## 1. 결론부터

1. **새로 짓습니다.** 저장소에는 기존 소스가 없었고(README 한 개), 운영 사이트는 노코드 빌더로 만든 화면 위주의 MVP 입니다. 온라인 결제, 좌석 유형, 대기, 정산, 권한 분리가 없고 상품 데이터도 0건이라, 고치는 것보다 같은 스택(Next.js)으로 다시 설계하는 편이 안전하고 빠릅니다. 기존 운영 사이트와 DB 는 건드리지 않습니다.
2. **서비스의 정의를 바꿉니다.** "빈자리 목록"이 아니라 **"지금 확정되는 자리를 시간순으로 보여 주는 전광판 + 사업자의 예약 장부"** 입니다. 떨이 할인 사이트가 아니라는 점(정가 거래 가능)을 화면·문구·수익모델 전체에서 지킵니다.
3. **공급이 먼저입니다.** 마켓 수요가 0이어도 사업자가 쓸 이유가 있도록 수수료 0%의 예약 장부(직접 입력 예약, 자체 예약 링크, 체크인, 고객 관리)를 먼저 줍니다. 취소가 장부에서 일어나야 그 자리가 곧 공석으로 올라옵니다.

## 4. 수익모델(운영 설정으로 조정 가능한 제안값)

- 고객 수수료 0원. 표시 가격 = 결제 금액.
- 사업자 중개 수수료(결제 수수료 포함 단일 요율): 남는자리로 처음 온 고객 9.9%(프로 6.9%), 재방문 4.9%, 1인당 상한 10,000원.
- 사업자 자체 링크·직접 입력·가져온 고객은 0%(온라인 결제 시 결제 실비만).
- 입점 프로모션: 승인 후 30건 또는 6개월 중개 수수료 0%.
- 구독(프로 월 19,900원): 운영 효율·성장 도구(자동 메시지 편집, 고급 분석, 고객 내보내기, 구성원). 자리를 채우는 기능은 무료.
- 하지 않는 것: 광고·상위 노출 판매, 고객 수수료, 약정·위약금, 비공개 요율.

판정 규칙은 `02-architecture.md` 6.6, 근거와 벤치마크는 `01-market-research.md` 6장에 있습니다.

## 6. 디자인 계획

1. 서로 다른 4개 아트 디렉션을 실제 화면으로 만들고 3개 관점(브랜드·사용성·시스템)으로 심사 → **"전광판"** 방향 선정. 출발 안내판처럼 시간이 가장 큰 정보이고, 남은 자리가 신호색 한 가지로 켜집니다.
2. 디자인 리서치(한글 가독성, 20–30대 고객과 사업자 선호, 예약 전환 UX, 국내외 서비스 실측, 색·접근성, 사진·정보 밀도)를 측정 가능한 기준으로 정리.
3. 리서치 기준으로 디자인 시스템을 다듬고 페르소나(20대 여성 고객, 30대 남성 고객, 40–50대 사업자, 접근성 전문가) 평가를 거쳐 수정.
4. 구현 후 전 화면을 모바일·PC 스크린샷으로 찍어 체크리스트로 검수하고 수정 반복.

## 8. 실제 운영에 추가 설정이 필요한 것

코드는 준비했지만 계약·심사·키 발급이 있어야 실제로 동작하는 항목입니다. 연동 전에는 화면과 운영자 콘솔의 "연동 상태"에 **모의/미연동**으로 표시됩니다.

| 항목 | 연동 전 동작 | 필요한 것 |
| --- | --- | --- |
| 결제(토스페이먼츠) | 테스트 결제(실제 청구 없음). 운영 모드에서는 시연 배포(`DEMO_MODE=1`)에서만 허용 | 가맹 계약·심사, 라이브 키, 웹훅 등록 |
| 판매자 정산 송금 | 정산 집계·확인·"지급 완료" 기록만(실제 송금은 수동) | 지급대행 계약 또는 계좌 이체 운영, 전자금융거래법 자문 |
| 구독료 자동결제 | 운영자가 수동으로 플랜 부여 | PG 정기결제 계약 |
| 문자·알림톡(SOLAPI) | 발송 대기열에 기록만(SIMULATED). 알림톡은 문자로 대체 | 발신번호 등록, 카카오 비즈니스 채널, 템플릿 심사, 080 수신거부 |
| 이메일(Resend) | 기록만 | API 키, 발신 도메인 인증 |
