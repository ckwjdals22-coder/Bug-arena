> 기준일 2026-11-27. 8개 세그먼트를 병렬 조사한 결과(플랫폼·제도 110여 건, 중복 포함)를 하나로 합치고 중복을 걷어낸 문서입니다.
> 이 단계에서는 **새로운 웹 검증을 하지 않았고**, 조사 결과에 담긴 근거 URL만 사용했습니다.

읽는 법

- 우선순위: **[필수]** 상용화 전에 반영 · **[권장]** 1차 고도화 · **[추후]** 데이터·외부 계약이 생긴 뒤

## 1. 요약

1. 가장 가까운 선례는 테이블링 '빈자리선점'과 캐치테이블 '빈자리 알림'입니다. 둘 다 "동시에 알리고 먼저 잡는 사람이 갖는" 구조라 알림을 받고도 허탕 치는 경험이 반복됩니다. **순번 우선권(좌석 홀드) → 미응답 시 자동 승계 → 임박하면 동시 선착순**이 남는자리의 1차 차별점입니다.
2. 초기 업종(소개팅·소셜 모임)에서 좌석 단위는 '정원'이 아니라 **성별(+출생연도) 좌석 풀**입니다. 업계는 '여성2자리 가능', '<남자마감>'을 손으로 적고 있고, 실시간 성별 잔여석을 정확히 보여주는 곳은 조사 범위에 없었습니다.
3. 업계 환불 규정은 행사 2~7일 전부터 0%입니다. 취소한 사람은 돈을 잃고 사업자는 성비가 깨진 채 진행합니다. **"그 자리가 다시 팔리면 환불을 올려 주는" 재판매 연동 환불**은 완성된 선례가 없는 공백입니다(연인어때의 '대체 참가자 확정 시 80%'가 부분 선례).
4. 임박 전용 서비스는 전부 사전예약으로 넓혔거나(HotelTonight, 데일리호텔) 사라졌습니다(YPlan). 살아남는 방법은 **사업자의 정원 장부**가 되는 것입니다. 전화·DM 예약 수기 등록과 자체 예약 링크를 수수료 0%로 줘야 취소석이 플랫폼 안에서 생깁니다.
5. '할인'이 아니라 **'지금 확정되는 자리'**로 보여 줘야 합니다. 무제한·반값 딜(Groupon)은 참여 사업자의 26.6%에 손실을 냈습니다. 정가가 기본이고, 가격 조정은 사업자가 켜는 선택 기능(하한가·공개 범위 통제)입니다.
6. 수익모델은 **플랫폼이 채운 자리에만 과금**합니다. 마켓 신규 9.9%(결제 수수료 포함) · 마켓 재방문 4.9% · 자체 링크·수기 0%, 고객 수수료 0원, Pro 월 19,900원(수수료 3%p 인하). 국내 벤치마크는 문토 20%, 프립 19.8%, 럭키밀 20%, 플랩 게스트 모집 10%입니다.
7. 남는자리는 법적으로 **통신판매중개자**입니다. 중개 고지와 판매자 신원정보, 다크패턴 금지(첫 화면 총액·사전선택 금지·쉬운 취소), 실제 재고만 표시, 후기 정책 공개(2026.7.21 시행), 분쟁 3·10영업일 통지가 화면과 운영 도구에 들어가야 합니다.
8. 가장 큰 미확정 위험은 정산입니다. 판매대금을 받아 사업자에게 넘기는 행위는 전자금융거래법상 PG에 해당할 수 있어(2026.12.17 개정 시행으로 '부수적 정산' 제외 단서 신설) **PG 지급대행을 쓰고 법률 자문으로 확정**해야 합니다. 국내 PG 빌링키는 정기 구독 전용이라 '카드만 등록하고 노쇼 때 청구', '대기 자동결제'는 지금은 불가로 봅니다.
9. 알림은 인앱 알림함이 원본이고 알림톡·문자는 교체 가능한 어댑터입니다. 정보성과 광고성을 나누고 야간(21~08시) 제한을 지킵니다. **실결제·정산 송금·알림톡 발송·본인확인은 모두 외부 계약이 필요하므로 구현 완료로 표기하면 안 됩니다.**
10. 대전은 수요에 비해 공급이 얇습니다. 공공 만남 행사는 30명 모집에 650명이 지원했는데, 일정 애그리게이터에 실린 105건 중 대전은 4건(1개 업체)입니다. **소수 사업자 직접 영업과 대리 등록**으로 "이번 주 대전 남는자리 0건"부터 없애야 합니다.

## 4. 남는자리가 반영할 인사이트

### 4.1 고객

- **[필수] CU-1 성별·조건별 잔여석을 가장 먼저 보여 준다.** 카드와 상세에 '여성석 2 / 남성석 마감(대기 3)', 검색 기본값은 '내 조건으로 지금 예약 가능한 자리'. 업계는 잔여석을 손으로 적고 애그리게이터도 '실시간이 아니다'라고 고지한다. [D1], [D3], [D5]
- **[필수] CU-2 순번 대기와 우선 결제권.** 마감 회차를 숨기지 않고 '대기 신청'으로 바꾸고, 내 순번과 오퍼 만료 시각을 보여 주며, 미결제 시 다음 순번으로 넘긴다. 대기는 좌석 풀(남성석·여성석)별로 받는다 — 수요가 남초라서다(대전 공공 행사 지원자 남 531 : 여 119, 모임 앱 평균 성비 6:4). 선착순 알림은 "들어가면 이미 늦다"는 경험을 만든다. [A1], [A2], [B22], [C1], [D11], [D12]
- **[필수] CU-3 처음부터 총액, 고객 수수료 0원.** 목록·상세·결제 금액이 같아야 한다. 추가 비용은 결제 이탈 사유 1위(40%)이고 결제 단계 가격 변동은 다크패턴 유형이다. [H8], [F9], [G23]
- **[필수] CU-4 환불액 미리보기와 2탭 취소.** "지금 취소하면 ○원 환불"을 서버 계산으로 보여 주고 부분취소 한 번으로 끝낸다. 소개팅 서비스 소비자 상담의 67.6%가 해지·위약금 문제다. [D18], [E7], [E5]
- **[필수] CU-5 개최 확정 진행 표시.** '확정까지 여성 1명 → 마감까지 2자리 → 확정됨' 3단계, 미달이면 자동 전액 환불. 고객의 가장 큰 불안은 "결제했는데 열리긴 하나"다. [E5], [D9]

- **[권장] TS-9 성비 보장 배지와 호스트 도착 확인.** 확정 성비와의 편차가 설정값을 넘으면 부분·전액 환불(사업자 선택). [D6], [E5]
- **[권장] TS-10 위험 점수.** 취소율, '취소 직후 다른 계정 예약' 패턴, 노쇼 이력으로 계산하고 고위험 예약에는 리마인드를 더 보낸다. [C23], [C40]
- **[추후] TS-11 상호 선택 시에만 연락처 전달.** [D9], [D15]

### 4.6 법·규제

- **[필수] LG-4 후기 운영정책 공개.** 작성 권한, 게시기간, 평점 산정, 삭제 기준, 이의절차. [G1], [G31], [G32]

- **[필수] LG-8 결혼중개업 경계.** 플랫폼 문구는 '좌석 예약', '성혼·매칭 보장'은 금칙어, 소개팅 업종은 결혼중개업 신고 여부와 보증보험을 입점 심사에서 받아 상세에 표시. 2020년 공정위는 소개팅 앱 6개사를 전자상거래법 위반으로 제재했다. [G48], [D24], [D25], [G51]

### 4.7 기술

- **[필수] TE-1 단일 재고 원장과 조건부 UPDATE.** 회차 × 좌석 풀(성별·출생연도 범위·정원·가격), 확정·홀드·오퍼를 한 카운터로 관리, DB CHECK 제약, 동시 요청 테스트. 채널이 늘면 중복 예약은 구조적으로 생긴다. [A34], [A16], [B2]
- **[필수] TE-2 홀드를 1급 개념으로.** 결제 홀드는 10분 이내(토스 결제 인증 후 10분 안에 승인해야 하는 제약과 맞춤), 만료 시 좌석 복원 → 대기 오퍼, 예약 생성과 결제 콜백에 멱등 키. [G15], [C13], [C10]
- **[필수] TE-3 대기 오퍼 엔진(모두 제안값).** 시작 24시간 이상 전: 순번대로 1명씩 30분 / 24~3시간 전: 순번, 응답 시간은 남은 시간의 10%(최소 15분) / 3시간 이내: 같은 좌석 풀 대기자 전원에게 동시 발송 후 선착순. 응답 시간과 결제 시간을 나누고, 연속 무응답이면 대기를 자동 해제하며, 야간에는 응답 시간을 늘린다. [C1], [C2], [C3], [C10], [E6]
- **[필수] TE-4 회차 상태와 확정 판정.** 모집중 → 개최 확정 → 마감 → 진행 → 종료 / 미달 취소. 사업자가 정한 판정 시각에 스케줄러가 확정 또는 미달 취소(자동 전액 환불)로 넘긴다. [D9], [E5], [E1]
- **[필수] TE-5 결제 무결성.** 서버 금액 검증 → 승인 → 웹훅(서명 검증, 이벤트 ID 멱등, 결제 재조회). 승인 후 좌석 확정에 실패하면 자동 전액 취소, 결제는 됐는데 예약이 없는 건을 찾는 대사 작업. 초기 결제수단은 카드·간편결제(가상계좌는 환불 계좌 수집이 필요해 제외). [G15], [G16], [G17], [G18]
- **[필수] TE-6 외부 연동 어댑터.** 결제·정산 송금·메시지·본인확인·사업자 검증·지도를 인터페이스로 두고 모의 / 테스트 / 실연동을 환경변수로 바꾼다. [G53], [G54], [G10]
- **[필수] TE-7 알림 구조.** 인앱 알림함이 원본, 발송 대기열, 종류(거래성·광고성) 강제, 중복 방지 키, 야간 지연, 발송 로그(성공·실패·비용). [A35], [A16], [G41]
- **[필수] TE-8 보안 기준.** 운영자 개별 계정 + 2단계 인증 + 실패 잠금 + 유휴 만료, 권한 변경 이력 3년, 개인정보 접속기록 1년 이상, 계좌번호 AES-256-GCM, 명단 내보내기 사유 기록, 카드정보 미저장. 공용 비밀번호 방식은 기준 미달이다. [G36], [G37]
- **[필수] TE-9 이벤트 로그.** 검색, 노출, 조회, 홀드, 예약, 취소, 재등록, 대기 신청, 오퍼, 참석을 처음부터 구조화해 저장한다. [H32], [C5]
- **[필수] TE-10 환불 계산은 순수 함수.** 기준점은 항상 회차 시작 시각, 경계 시각 단위 테스트. 프립처럼 '신청 마감일' 기준이면 고객이 오해한다. [E1], [E5]
- **[권장] TE-11 웹 푸시와 홈 화면 추가.** 권한은 예약 완료·대기 신청 직후 안내를 거쳐 요청하고, iOS는 홈 화면에 추가한 웹앱에서만 푸시가 된다는 점을 안내한다. [H16], [H17], [H18]
- **[권장] TE-12 인앱 브라우저 대응.** 카카오톡·인스타그램·네이버 인앱 감지, 인앱에서는 Google 로그인 숨김, 로그인 → 결제까지 검증. [H24], [D21], [H25]
- **[추후] TE-13 POS·캘린더 연동, 규칙 기반 노쇼 위험 점수에서 예측 모델로.** [C44], [C40]

### 4.8 성장·디자인

- **[필수] GD-1 '지금 확정되는 자리'로 보여 준다.** 카드의 첫 정보는 '오늘 19:30 · 여성석 2 · 즉시 확정', 기본 정렬은 시작 임박순, 할인율순 정렬은 만들지 않는다. 공석 사유 라벨('취소로 생긴 자리', '추가 오픈')을 붙이고 '땡처리·떨이·마감세일'은 금지어. [B1], [B2], [B3], [B4]
- **[필수] GD-2 정보 순서: 언제 → 어디 → 몇 자리 → 총액 → 누가.** 상대·절대 시각 병기('오늘 19:30 · 2시간 뒤'), 칩은 오늘 / 내일 / 이번 주말 / 퇴근 후, 하단 탭은 홈 / 탐색 / 내 예약 / 관심·알림 / 마이. [H1], [H6], [H7]
- **[필수] GD-3 빈 화면이 전환을 만든다.** 리스팅이 0건이면 조건 알림 신청, '이런 모임을 찾아요' 수요 요청, 사업자용 '빈자리 등록' 진입을 보여 준다. 가짜 리스팅은 넣지 않는다. [H14], [B2]
- **[필수] GD-4 대전·한 카테고리에 집중.** 3개 권역(둔산·시청 / 유성·봉명 / 원도심)에서 활성 사업자 20~30곳·주 60회차(가설)를 채우기 전에는 수요 광고를 하지 않고, 다른 지역은 '오픈 알림'만 받는다. 대전은 인구 약 144만, 청년 비율 28.6%(특·광역시 2위)다. [H27], [H29], [D5], [D11], [D35]
- **[필수] GD-5 공유되는 상품·사업자 페이지.** 로그인 없이 열리는 URL, 동적 OG 이미지(제목·일시·지역·가격, 잔여석 제외), 구조화 데이터(Event·Offer), 사업자 미니 페이지와 QR(수수료 0%), 공유자·채널 파라미터. [H23], [H19], [F1], [A42]
- **[필수] GD-6 접근성.** 본문 대비 4.5:1, 터치 44px, 상태를 색만으로 표현하지 않음, 타이머는 60초·20초 시점에만 스크린리더로 안내, 드래그 UI에 버튼 대안, 하단 고정 버튼이 입력 포커스를 가리지 않게. [H5], [H10], [H15], [H4]
- **[필수] GD-7 문구 규칙.** 버튼은 결과와 금액('32,000원 결제하고 자리 확정'), 손실 강조 금지, 해요체. [H6]
- **[권장] GD-8 지역 2단계.** 시·도 > 권역 > 동네, 지하철 역명 보조 태그, 공개 위치(동·역)와 상세 주소(확정자만) 분리. [D4], [D39], [D40]
- **[권장] GD-9 소개팅 전용 속성.** 형식, 좌석 풀·출생연도 범위, 미혼·돌싱 대상, 대화 시간·총 시간, 포함 내역, 필요한 배지, 결과 전달 방식 → 카드 요약 '10분×8명 · 여성석 2 · 94~01년생 · 둔산동'. [D37], [D6], [D16]
- **[권장] GD-10 고정 다이제스트 하루 2회.** 11시 '오늘의 남는자리', 17시 '오늘 저녁 임박' — 광고성 수신 동의자에게만. [B24], [B3]
- **[권장] GD-11 사업자 공유 키트.** 링크, QR, 스토리 카드(9:16 이미지), 카카오톡 공유. [H21], [H22], [H19]
- **[권장] GD-12 바텀시트·스켈레톤 규칙.** 시트는 한 화면짜리 과업(인원·필터·공유·대기·신고)에만, 결제는 전체 페이지, 300ms 미만 응답에는 스켈레톤 생략. [H11], [H12], [H13]
- **[권장] GD-13 추천 보상은 '첫 참석 완료' 기준, 참석 고객의 호스트 전환 유도.** [H30]
- **[추후] GD-14 업종 프리셋으로 확장.** 정원형 세션(클래스·풋살 게스트·골프 조인) → 1인 슬롯(뷰티·PT). [E5], [E19]

## 5. 요청하지 않았지만 추가를 권하는 기능

요청서의 기능 목록에는 없지만, 조사 결과 서비스가 실제로 돌아가려면 필요하다고 판단한 것들입니다.

| # | 기능 | 왜 필요한가 | 관련 항목 |
| --- | --- | --- | --- |
| 1 | 성별·조건별 좌석 풀과 풀별 대기열 | 요청은 '정원 관리'였지만 초기 업종에서 정원은 숫자 하나가 아니다. 남녀 좌석이 따로 팔리고 따로 마감된다. 식당·미용 확장 때는 '무관' 풀 하나로 같은 모델을 쓴다 | CU-1, TE-1 |

## 6. 권장 수익모델

### 6.1 원칙

1. **플랫폼이 채운 자리에만 받는다.** 사업자가 직접 데려온 고객과 수기 예약에는 중개 수수료가 없다.
2. **고객에게는 받지 않는다.** 표시 가격이 곧 결제 금액이다.
3. **유동성을 만드는 기능은 무료다.** 대기, 취소석 재등록, 수기 예약, 자체 링크, 체크인, 환불 정책은 요금제로 막지 않는다. 구독은 운영 효율과 성장 도구에 받는다.
4. **요율과 판정 규칙을 공개한다.** 약정·위약금·광고 상품·비공개 요율은 두지 않는다.

## 9. 검증하지 못한 항목

### 9.1 조사 방법의 한계

- 이 문서는 8개 조사 결과를 합친 것이며 **합치는 단계에서 원문을 다시 열어 확인하지 않았습니다.**
- SaaS·규제·UX 세그먼트는 웹 검색 한도가 소진되어 공식 페이지를 직접 여는 방식으로만 조사했습니다. 언론 보도, 앱 리뷰, 국내 사업자 커뮤니티의 불만은 교차 확인하지 못했습니다.
- 접근이 막혀 검색 결과 요약이나 제3자 페이지에 의존한 곳: 캐치테이블 B2B 사이트, Tock·DICE·Booksy·ClassPass 도움말, 모드파티·연인어때 공식 사이트, 문토 FAQ 본문, 타임티켓 FAQ, 블라인드 게시글, 일부 기사 원문.
- 프립의 데이터 구조와 솜씨당의 환불·정산 문구는 공개 웹앱 번들에서 읽은 것이라 실제 서버 정책과 다를 수 있습니다.
- 공정위·금융위 보도자료는 번호만 확인된 것이 있어 출처 목록에 번호로 표기했습니다.

### 9.2 확인하지 못한 사실

- 캐치테이블 빈자리 알림의 세부 규칙(동시·순차, 신청 한도)과 '예약금 0원 결제'의 현재 운영 상태
- 테이블링 현재 요금, 네이버 예약 공식 수수료표와 대기 기능 유무, 카카오톡 예약하기 결제 수수료율
- 문토 현재 수수료(2023년 게시 기준 20%), 솜씨당 18%·탈잉 15%(블로그 출처), 프립(19.8% vs 9.9%)
- HotelTonight·Dayuse·ClassPass·FunNow·라스트오더의 실제 수수료율
- 토스 지급대행 수수료, 포트원 결제·정산·본인확인 요금, 본인확인 건당 단가, NHN Cloud 단가, 네이버 지도 요금
- 헤이뷰티·Ambl·Lately 등의 현재 운영 여부
- 대전의 인스타그램·오픈채팅 기반 개인 모임 운영자 실태, 대학 재학생 수, 상권별 20~30대 유동 인구

### 9.3 회사가 스스로 발표한 수치

Tock 노쇼율(0.9 / 1.7 / 3%), Fresha 노쇼 89% 감소, Booksy 취소 20% 감소, StyleSeat 연평균 충원액, ClassPass 예약·매출 증가, SevenRooms·Waitly·TurnUp 성과, 테이블매니저 매출 34% 성장, 럭키밀 이탈률 2% 미만, 러브매칭 누적 참가자. 독립 검증이 없습니다.

### 9.4 법 해석이 필요한 부분

- 통신판매중개의 '부수적 정산'이 PG 등록에서 제외되는 범위(시행령은 입법예고 단계까지만 확인)
- 소개팅·로테이션 미팅 좌석 중개에 결혼중개업법이 적용되는지
- 날짜가 정해진 예약 상품의 청약철회 7일과 취소 수수료의 관계, 에스크로 적용 제외 여부
- 소개팅·모임·클래스에 적용할 공식 위약금 기준 — 확인된 수치는 음식점 대상이고 권고 기준입니다
- 조건·팔로우 기반 빈자리 알림이 정보성인지 광고성인지(이 문서는 광고성으로 보수적으로 분류)
- 할인율 기준가의 '최근 20일 최저가' 기준, 다크패턴 과태료 수준(기사와 조문의 수치가 다름)
- 성별 차등 가격, 개인 간 예약 양도의 약관·법적 적합성
- 전자상거래법 시행령 세부(반복 간섭 예외 기간, 총금액 표시 예외), 정보통신망법의 '(광고)' 표기 방법

### 9.5 근거가 아니라 제안인 수치

수수료 9.9 / 4.9%와 건당 상한 10,000원, 구독 19,900 / 49,000원, 런칭 프로모션(30건 또는 6개월), 결제 홀드 10분, 대기 응답 30분 / 남은 시간의 10% / 3시간 기준, 무료 취소 30분, 재판매 환불 70~90%, 노쇼 제재 단계, 구매 한도 2, 채널 의존도 30%, 공급 목표(사업자 20~30곳·주 60회차), 권역 분류안. 모두 운영 데이터로 조정해야 합니다.

### 9.6 직접 선례를 찾지 못한 자체 제안

- 재판매 연동 환불의 완성형(연인어때의 대체 참가자 환불, DICE·Resident Advisor의 정가 재판매 대기열이 부분 선례)
- 성별 좌석 풀 단위의 대기열과 '짝 맞춤 승격'

### 9.7 기술적으로 실기기 확인이 필요한 것

- 카카오톡 인앱에서 외부 브라우저를 여는 방식은 공식 문서가 아닌 개발자 블로그가 출처입니다 [H25]
