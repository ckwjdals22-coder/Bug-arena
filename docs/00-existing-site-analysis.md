# 기존 사이트 분석 (2026-11-27 기준)

대상: https://app-1828ec9702.serion.dev/

> 저장소에는 `README.md` 한 개만 있었고 기존 사이트의 소스코드는 포함되어 있지 않았습니다.
> 그래서 운영 중인 사이트를 **읽기 전용으로** 크롤링하고(페이지·공개 API·번들 분석) 구조를 역으로 파악했습니다.
> 운영 데이터에 영향을 주지 않기 위해 회원가입·로그인 등 쓰기 동작은 하지 않았습니다.
> 따라서 로그인 뒤 화면(예약내역·사업자 센터·관리자)은 번들에 남은 문자열과 API 응답으로 추정한 내용입니다.

## 1. 구성

| 항목 | 확인한 내용 |
| --- | --- |
| 프레임워크 | Next.js (App Router, Turbopack), React 서버 컴포넌트 |
| 제작 도구 | 노코드/AI 빌더(Foundry, `serion.dev` 호스팅) — 오류 화면에 "Foundry에서 이 앱을 열고…" 문구 |
| 데이터 | Prisma 계열 ORM 추정(cuid 형식 ID). 분류 5종만 존재, **등록 상품 0건** |
| 폰트·스타일 | Pretendard(CDN), Tailwind, 보라 그라디언트 + 골드 버튼, 이모지 분류 칩, Unsplash 핫링크 |

### 화면

| 경로 | 내용 |
| --- | --- |
| `/` | 히어로 + 분류 칩 + "지금 예약할 수 있는 자리" 피드(정렬: 빠른 일정/낮은 가격/최신) |
| `/search` | 검색어·분류·지역·날짜·가격 필터 |
| `/login`, `/signup` | 이메일·비밀번호. 가입 시 "예약하는 고객 / 자리를 파는 사업자" 선택, 사업자는 상호 입력 |
| `/mypage` | 예약내역(로그인 필요) |
| `/seller`, `/seller/products` | 사업자 상품 등록·관리(로그인 필요) |
| `/admin` | **공용 비밀번호 하나**로 들어가는 관리자 화면 |

### 공개 API

| 엔드포인트 | 응답 |
| --- | --- |
| `GET /api/products?sort&page&category&q&region&date&minPrice&maxPrice` | `{ items, total, hasMore }` — 항목 필드: `title, summary, image, businessName, region, category, nextStart, remaining, minPrice, isSample` |
| `GET /api/products/:id` | 상품 상세(없으면 404 JSON) |
| `GET /api/categories` | 원데이클래스 / 소개팅 / 스포츠 / 뷰티 / 기타 |
| `GET /api/auth/me`, `POST /api/auth/{login,signup,logout}` | 세션 |
| `GET /api/bookings` | 내 예약(401) |
| `GET /api/seller/products` | 사업자 상품(401) |
| `POST /api/admin/login` | 관리자 비밀번호 확인(실패 누적 시 10분 잠금) |

번들에 남은 상태값: 상품 `판매중 / 판매중지 / 임시저장`, 예약 `예약 확정 / 결제 확인됨 / 현장 결제 예정 / 취소됨 / 취소(결제 없음) / 환불 대기 / 환불 완료`.
→ 결제는 온라인 PG 가 아니라 **현장 결제 또는 사업자가 수동으로 "결제 확인"** 하는 방식으로 보입니다.

## 2. 유지할 점

- "남는 자리를 시간순으로 본다"는 핵심 관점(빠른 일정순 기본 정렬, 남은 자리 수 표시, 마감 임박 표시)
- 고객/사업자 이원 가입, 사업자 센터와 관리자 분리
- 분류 체계(원데이클래스·소개팅·스포츠·뷰티)와 지역·날짜·가격 필터
- Pretendard 기반의 한국어 가독성

## 3. 부족한 점

### 기능

| 영역 | 문제 |
| --- | --- |
| 재고 | 좌석 유형(성별 정원 등) 개념이 없음. 소개팅·소셜 모임의 핵심인 **성비별 잔여석**을 표현할 수 없음 |
| 예약 | 온라인 결제·환불 없음, 좌석 홀드/동시 예약 충돌 방지 여부 확인 불가 |
| 공석 | "취소석 / 노쇼 / 미판매" 구분, 취소석 재등록, 대기 신청, 빈자리 알림 없음 |
| 고객 | 관심 상품, 알림함, 후기, 맞춤 알림 조건 없음 |
| 사업자 | 일정·정원 달력, 고객 관리(CRM), 대기자 관리, 자동 문자, 체크인, 매출·충원율 분석, 정산 없음 |
| 운영 | 입점 심사, 정산, 신고·분쟁, 통계, 권한 분리, 감사 기록 없음 |
| 법적 표시 | 이용약관·개인정보처리방침·사업자 정보·통신판매중개 고지 없음 |

### 보안

| 항목 | 상태 |
| --- | --- |
| 보안 헤더 | CSP, HSTS, X-Frame-Options, Referrer-Policy 등 **전부 없음**. `X-Powered-By: Next.js` 노출 |
| 관리자 인증 | 계정이 아닌 **공용 비밀번호 1개**(누가 무엇을 했는지 추적 불가, 2단계 인증 없음) |
| 약관 동의 | 가입 시 약관·개인정보 수집 동의 절차 없음 |
| 검색 노출 | `robots.txt`, `sitemap.xml`, 웹 앱 매니페스트 없음 |

### 디자인

- 보라 그라디언트 히어로, 골드 알약 버튼, 이모지 분류 칩, 스톡 사진 콜라주 등 **AI 생성 템플릿의 전형적 인상**
- "시간이 핵심인 재고"라는 서비스 성격이 화면 구조에 드러나지 않음(일반 상품 카드 목록과 차이가 없음)
- 데스크톱은 모바일 화면을 넓힌 수준

## 4. 데이터 이전에 대하여

- 현재 운영 DB 에는 분류 5건 외에 상품이 없어, 이전할 거래 데이터는 사실상 없습니다(회원 수는 외부에서 확인 불가).
- 새 플랫폼의 분류는 기존 slug(`class`, `meet`, `sports`, `beauty`, `etc`)를 그대로 포함하도록 시드했습니다.
- 기존 회원을 옮기려면 Foundry 에서 DB 를 내보내야 하며, 비밀번호 해시 방식이 다르면 "비밀번호 재설정" 안내로 전환해야 합니다.
